Python for Molecular Sciences:
Review: Declaration vs Definition

You Already Know This Concept

Remember from Week 2: variables can be declared separately from their definition.

Variables

  • Declaration: "This variable exists somewhere"
  • Definition: "Here's the actual variable and its value"

Functions Work the Same Way

  • Declaration: "This function exists somewhere"
  • Definition: "Here's the actual function body"

This solves the ordering problem in C++.


#include <iostream>

// Function declaration (just the signature)
int helper(int x);

int main() {
    int result = helper(5);  // OK - compiler knows signature
    std::cout << result << std::endl;
    return 0;
}

// Function definition (the actual implementation)
int helper(int x) {
    return x * 2;
}
Tells compiler: "helper exists, takes int, returns int"
Provides the actual implementation

Problem: Sharing Functions Across Files

I Want to Reuse My Function

You wrote a useful function and want to use it in multiple programs:

Option 1: Copy-Paste

  • Copy function declaration and definition to each file
  • Hard to maintain - if you fix a bug, must fix in all copies
  • Violates "Don't Repeat Yourself" principle

Option 2: Include .cpp Files?

  • You might think: #include "math_funcs.cpp"
  • This includes the entire function body
  • Causes "multiple definition" errors during linking

Better Solution: Headers

Share just the declarations, keep definitions separate.

The Problem
program1.cpp:
- Needs calculateArea()
- Must copy declaration and definition

program2.cpp:
- Also needs calculateArea()
- Must copy declaration and definition again

Result:
- Code duplication
- Maintenance nightmare
- Bug fixes need to be made everywhere
The Solution
math_utils.h: Declarations only
math_utils.cpp: Definitions only

program1.cpp: #include "math_utils.h"
program2.cpp: #include "math_utils.h"

Result:
- No duplication
- Single source of truth
- Easy to maintain

Headers: Shared Declarations

Headers Let You Share Declarations

A header file contains just the declarations that multiple files need to know about:

What Goes in Headers (.h)

  • Function declarations
  • Constants
  • Type definitions
  • Class declarations (later)

What Goes in Source (.cpp)

  • Function definitions
  • Variable definitions
  • The actual implementation code

Key idea: Headers answer "what exists?" and source files answer "how does it work?"

math_utils.h

// Function declarations only
double calculateArea(double radius);
double calculateVolume(double radius, double height);

// Constants
const double PI = 3.14159;
math_utils.cpp

#include "math_utils.h"

// Function definitions
double calculateArea(double radius) {
    return PI * radius * radius;
}

double calculateVolume(double radius, double height) {
    return calculateArea(radius) * height;
}

Using Headers in Your Program

Include the Header to Use the Functions

Any file that wants to use your functions includes the header:

Include Syntax

  • #include "myheader.h" - Your files (quotes)
  • #include <iostream> - System files (brackets)

What Happens

  1. Preprocessor copies header content into your file
  2. Compiler sees the function declarations
  3. Your code can call the functions
  4. Linker connects to the actual implementations

// main.cpp

#include <iostream>
#include "math_utils.h"  // Now I know about calculateArea

int main() {
    double radius = 5.0;
    double area = calculateArea(radius);  // OK - compiler knows signature
    
    std::cout << "Area: " << area << std::endl;
    
    return 0;
}
System header (angle brackets)
Custom header (quotes)
Function available because we included the declaration

Compilation

g++ main.cpp math_utils.cpp -o program

Compiles both .cpp files and links them together

Problem: Multiple Inclusion

Headers Can Be Included Multiple Times

As projects grow, the same header might get included multiple times in the same file:

How This Happens

  • You include math_utils.h
  • You also include file_io.h
  • But file_io.h also includes math_utils.h
  • Now math_utils.h is included twice!

The Problem

  • Function declarations appear twice
  • Compiler sees "redefinition" error
  • Constants defined multiple times

The Solution

Header guards ensure each header is only included once, no matter how many times it's requested.

The Problem

// main.cpp
#include "math_utils.h"  // Includes calculateArea declaration
#include "file_io.h"    // This ALSO includes math_utils.h!

// After preprocessing, this is what the compiler sees:
double calculateArea(double radius);  // From first include
double calculateArea(double radius);  // From second include - ERROR!

int main() {
    return 0;
}
Compiler error: 'calculateArea' redeclared
The Solution
Header guards prevent multiple inclusion:

1st time: "MATH_UTILS_H not defined → include content"
2nd time: "MATH_UTILS_H already defined → skip content"

Result: Declaration appears only once!
Python for Molecular Sciences:
Header Guards

Preventing Multiple Inclusion

Header guards use preprocessor directives to include content only once:

The Pattern

  1. #ifndef SYMBOL - "If symbol not defined..."
  2. #define SYMBOL - "Define it now"
  3. Put all header content here
  4. #endif - "End conditional block"

Naming Convention

  • Use filename in ALL_CAPS
  • Replace dots with underscores
  • Example: math_utils.h → MATH_UTILS_H

Always use this pattern in every header file!


// math_utils.h

#ifndef MATH_UTILS_H
#define MATH_UTILS_H

// All your header content goes here
double calculateArea(double radius);
double calculateVolume(double radius, double height);

const double PI = 3.14159;

#endif  // MATH_UTILS_H
"If MATH_UTILS_H is not defined..."
"...then define it and include this content"
Content is only included once

How It Works

1st inclusion: MATH_UTILS_H undefined → define it, include content
2nd inclusion: MATH_UTILS_H already defined → skip everything

Compilation Process

How Multi-File Projects Are Built

The compilation process involves several steps:

1. Preprocessing
Includes headers, processes #define directives
2. Compilation
Each .cpp file becomes an object file (.o)
3. Linking
Object files are combined into executable

Command Line

g++ main.cpp physics.cpp file_io.cpp -o simulation

Compiles all .cpp files and links them together

Compilation Flow

main.cpp
physics.cpp
↓ compile
main.o
physics.o
↓ link
simulation (executable)
Key Point: Headers (.h) are never compiled directly. They're included in .cpp files during preprocessing.

Using Headers in Your Program

Including and Using Custom Headers

To use functions from your custom headers:

Include Syntax

  • #include "myheader.h" - Your files (quotes)
  • #include <iostream> - System files (brackets)

What Happens

  1. Preprocessor copies header content
  2. Compiler sees function declarations
  3. Linker connects to implementations

Key insight: The compiler needs to know what functions exist (declarations) before you can call them. 


// main.cpp

#include <iostream>
#include "math_utils.h"  // Our custom header

int main() {
    double radius = 5.0;
    double height = 10.0;
    
    // Use functions declared in math_utils.h
    double area = calculateArea(radius);
    double volume = calculateVolume(radius, height);
    
    std::cout << "Area: " << area << std::endl;
    std::cout << "Volume: " << volume << std::endl;
    
    // Use constant from header
    std::cout << "PI value: " << PI << std::endl;
    
    return 0;
}
System header (brackets)
Custom header (quotes)
Functions are available because we included the header

Multi-File Best Practices

Guidelines for Success

✓ Do This

  • Always use header guards
  • Match .h and .cpp file names
  • Group related functions together
  • Include only what you need
  • Use meaningful file names

✗ Avoid This

  • Putting implementations in headers
  • Including .cpp files
  • Circular dependencies
  • Too many files for simple projects

💡 Tips

  • Start with 2-3 files, grow as needed
  • Use IDEs or Makefiles for compilation
  • Comment your header files well

// Good header structure (math_utils.h)
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

#include <vector>  // Only include what we need

// Clear, documented function declarations
/**
 * Calculates the mean of a vector of numbers
 * @param numbers Vector of double values
 * @return The arithmetic mean
 */
double calculateMean(const std::vector<double>& numbers);

// Constants for this module
const double PI = 3.14159265359;

#endif  // MATH_UTILS_H


// ✗ Bad practice - implementation in header
// DON'T DO THIS:
double badFunction(double x) {
    return x * x;  // Implementation belongs in .cpp!
}
Good: Clear structure with guards
Bad: Implementation in header file
